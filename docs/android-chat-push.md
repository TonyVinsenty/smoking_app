# Android: уведомления чатов

Клиент использует Firebase Cloud Messaging. По решению владельца 2026-11-06 отправка переносится в Cloudflare Workers Free: Firebase остаётся на Spark, Blaze не подключается из-за требования предоплаты. Worker раз в минуту ищет новые сообщения и отправляет push текущим получателям. На Android устанавливать APK 27 или новее: в 26 обнаружен конфликт инициализации Firebase, приводящий к чёрному экрану; обновлять поверх существующей версии. Отправителям на iPhone обновление не требуется. Редактирование и служебные события не уведомляют. Токены лежат в `users/{uid}/devices/{deviceId}` и закрыты от других пользователей. Удаление аккаунта удаляет зарегистрированные устройства.

## Публикация

Нужны бесплатный аккаунт Cloudflare, Wrangler и отдельная служебная учётная запись Firebase с чтением Firestore и отправкой FCM. Передача приватного ключа в защищённый секрет Worker требует явного подтверждения владельца. Исходный ключ не попадает в приложение или Git. Детальная инструкция и ограничения — `worker/README.md`. Предварительные проверки:

```powershell
node tool/sync_push_strings.cjs
node --test worker/test/poll.test.mjs
firebase deploy --only firestore:rules,firestore:indexes --project zero-91cc8
```

Далее публикуется `worker/wrangler.jsonc`, загружается секрет `GOOGLE_SERVICE_ACCOUNT` и включается `PUSH_ENABLED`. Сначала Worker развёрнут с отправкой выключенной. При первом включении история до этого момента не уведомляет. Обычно задержка составляет около минуты; ограничения бесплатного тарифа, большая очередь и сбои могут увеличить её. Cloud Functions не публикуются; прежний код в `functions/` оставлен как предыдущая реализация и набор тестов правил.

Android-сборка читает `firebase/google-services.json` и создаёт нативные ресурсы Firebase: они нужны для получения push после завершения процесса, ещё до запуска Dart. Этот файл не публикуется в git. Локальная конфигурация должна соответствовать `lib/firebase_options.dart`.

## Проверка на телефоне

1. Установить APK поверх предыдущего. Открыть приложение с созданным профилем друзей и разрешить уведомления Android.
2. Отправить сообщение со второго аккаунта в личный и групповой чат: проверить уведомление при свёрнутом и закрытом приложении, открытие нужного чата по нажатию, а также изображение без подписи.
3. В открытом чате не должно быть отдельного уведомления о его новом сообщении. Изменение сообщения и собственные сообщения не должны создавать уведомлений.
4. Запретить уведомления в настройках Android: они перестают показываться. После разрешения открыть приложение снова.
5. Для псевдонимов установить APK 28 или новее и один раз открыть приложение с интернетом. В личном push заголовок — свой псевдоним друга, в группе — `Название (Псевдоним)`; без псевдонима используется обычное имя. Изменение/удаление псевдонима обновляет закрытую копию в записи этого устройства в Firebase, друзья её не видят.

Нужны Google Play Services. После системной команды «Остановить принудительно» Android блокирует доставку до следующего открытия приложения. Доставку в реальном фоне нельзя подтвердить одной компиляцией или тестами правил.

## Локальные проверки правил

В `functions/` установлены зависимости для тестов (`pnpm install`). Запуск из корня:

```powershell
firebase emulators:exec --only firestore --project demo-zero "node --test functions/test/firestore.test.cjs"
```

Используется отдельный демонстрационный проект и порт 8087, реальные данные не меняются.

iOS: push не включён; автоматическая регистрация Messaging отключена в Info.plist. Для запуска позже нужны Apple Developer, APNs-ключ в Firebase и возможности Push Notifications / Remote notifications в Xcode.
